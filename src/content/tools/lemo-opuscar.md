## What it does

[Lemo-Opuscar](https://github.com/lemomo-ai/lemo-opuscar) is a **collection of film styles plus a Claude Code plugin/Agent Skill**. Each library style has a prompt and a demonstration film created primarily through code, Canvas/WebGL rendering, and media tooling, rather than a text-to-video model. The [official style gallery](https://lemomo-ai.github.io/lemo-opuscar/) and [style index](https://github.com/lemomo-ai/lemo-opuscar/blob/main/styles/README.md) show the supported directions.

The core gallery documents **66 ready-to-use styles**, while the separate *OPUSCAR 98* project illustrates **98 film-specific styles**; these counts describe different collections rather than a single set of 164 catalog entries.

## Where it fits

- **Documentary and historical narratives:** explore archive light tables, visual investigations, halftone dossiers, engraving, and 1920s newsreel aesthetics.
- **Distinctive educational video:** try data physicalization, animated maps, whiteboard explainers, and diagram-driven scenes.
- **Visual identity and shorts:** experiment with stained glass, impasto oil painting, watercolor, Swiss motion graphics, and short original title sequences.
- **Repeatability:** save custom styles instead of rewriting directions for every production.

It complements [HyperFrames](https://github.com/heygen-com/hyperframes), [Remotion](https://github.com/remotion-dev/remotion), and other code-based motion workflows. It is **not** a replacement for every rendering pipeline or a duplicate record of any individual style or generic motion prompt.

## Installation and operation

The upstream Claude Code installation instructions are:

```bash
claude plugin marketplace add lemomo-ai/lemo-opuscar
claude plugin install lemo-opuscar@lemolab
```

Review the source and scripts before installing. The plugin may fetch shared guides and assets to `~/lemo-opuscar` and project outputs into the directory from which the skill is invoked. It expects Node 20+, FFmpeg 7+, and Python 3.11+ (or uv), and production can consume substantial model tokens and compute.

Upstream documentation explicitly says the styles were tuned for **Claude Opus 5.5**; portability to other agents or models must be tested, not assumed.
